# 先修学习路径与关系质量检查设计

## 目标

在现有软件工程课程学习平台中，让学习者围绕一个目标知识点查看必要的先修顺序和个人掌握情况；让管理员发现课程先修关系的数据质量问题。功能复用 MySQL `knowledge_point.prerequisites_json`、`knowledge_mastery`、现有课程阅读/练习页面和当前只读 NebulaGraph，不创建或写入图谱数据。

## 学习者路径

- 在现有知识图谱页增加“图谱浏览 / 先修路径”视图切换。
- 学习者选择一个课程知识点作为目标。后端仅读取该知识点所属启用课程中启用的知识点和先修 ID，递归取得目标的传递性先修点。
- 返回顺序必须满足先修点出现在其后继之前，并以目标点结束。重复节点去重；无效或课程外引用不会带入学习路径。
- 每个路径点返回课程/章节 ID、知识点 ID、名称、图谱实体、掌握度、先修 ID 和状态：`MASTERED`（掌握度 >= 60）、`IN_PROGRESS`（0 < 掌握度 < 60）、`UP_NEXT`（未掌握且其有效先修均已掌握）、`BLOCKED`（尚有未掌握的先修）。
- 路径页面显示当前目标、节点状态和掌握度，并分别链接到课程对应章节、该知识点练习，以及现有图谱实体。不得把掌握度解释为客观能力测量，只描述为系统内答题记录估计值。
- 先修数据若有循环，学习路径仍须有界、去重并返回目标；响应包含可见的路径数据质量提示，不因循环造成无限递归。

## 管理端质量检查

- 管理员按课程查看只读质量报告，不写回、不自动修复 `prerequisites_json`。
- 检查项：空或非数组 JSON、非正整数 ID、重复 ID、找不到的知识点 ID、自引用、引用其他课程的知识点、循环依赖。
- 每条问题至少提供稳定代码、严重级别、涉及知识点和简洁说明；报告包含检查知识点数、有效关系数、问题列表和汇总。
- 现有后台鉴权继续保护接口；普通学生不能访问质量报告。

## API

- `GET /api/knowledge/learning-path?targetId={knowledgePointId}`：已认证学习者接口，返回目标、按顺序排列的节点、每点状态和循环/无效关系提示。目标不存在或课程不可用时返回 404。
- `GET /api/admin/courses/{courseId}/prerequisite-quality`：ADMIN 专属只读质量报告。课程不存在返回 404。

## 兼容与边界

- 不增加运行时依赖或数据库迁移。
- 不改 Mecha-QA Python 源码、NebulaGraph 空间、AI 模型和原三种问答逻辑。
- 不重新定义或暗中修改现有推荐评分；路径页面只复用相同 60 分掌握阈值。
- 新接口的输出仅包含当前课程内启用知识点和当前用户掌握数据。
- 如果关系配置存在错误，用户界面显示可解释提示；管理员负责在现有课程/数据维护流程处理。

## 验收

- 自动化测试覆盖传递先修顺序、目标无先修、重复引用、无效引用、跨课程引用、自引用、循环有界性、掌握状态计算和管理员鉴权。
- 前端在图谱视图之间切换时保留原图谱查询能力；路径卡片的阅读、练习、图谱链接携带正确课程/章节/知识点参数。
- 管理员看到按课筛选的只读质量报告；无问题、部分问题和加载/错误状态均有明确反馈。
- Maven 完整测试、Vitest 全套和 Vite 生产构建通过。
