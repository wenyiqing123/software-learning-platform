# 学习平台功能扩展清单

更新日期：2026-11-19（F1–F8 首版功能完成）  
项目：基于知识图谱和大语言模型的智能化学习平台

## 规划原则

本清单把项目已有能力与待新增能力分开，避免将已完成模块重新包装成“新增功能”。新增重点不是继续堆页面，而是把课程阅读、图谱证据、练习反馈、复习安排和效果评价连接起来，形成可展示、可记录、可用于毕业设计研究的学习闭环。

毕业设计的特色建议表述为：**面向软件工程课程，将有证据约束的分层问答、基于学习状态的复习安排和学习过程评价整合到一个可追踪的平台。** 这是课程场景下的系统设计与应用特色，不声称提出了新的基础学习算法，也不预设认知负荷或学习成绩已经改善。

## 已有功能

下列能力在项目源码、接口或验收记录中已有实现，不计作待新增项：

- 软件工程课程章节、小节、学习目标、案例、延伸资源和个人阅读进度。
- 软件工程知识图谱浏览、三元组证据展示、实体问答跳转及基于先修关系的学习路径。
- AI 助教 DIRECT、TRIPLES、RANKED 三种模式；RANKED 策略与排序/评分消融实验；实验记录、参考答案指标、期望实体召回、人工评分、耗时和 JSON 导出。
- 单选、多选、判断题，作答判定与解析，个人错题列表、重新作答和手动标记已掌握。
- 按掌握度、错题、近期练习、先修关系和课程顺序计算的可解释推荐，以及个人答题概览。
- 学生与管理员账户；管理员维护课程、题目、课程知识点映射及先修关系质量检查。

项目边界继续保持：Mecha-QA Python 程序和 NebulaGraph 图空间只读；只通过既有 Python Bridge 检索；数据库结构只新增 V6 及之后的迁移，不修改已经应用的迁移。

### F2 的调度规则选择

当前首版采用可解释的固定间隔（10 分钟、1 天、3 天、7 天）以降低依赖复杂度。客观答错将下次间隔重置为10分钟，但仍原样记录用户主观回忆评分；连续三次答对且回忆评分至少“一般”时自动按复习规则标记掌握。该实现不是 FSRS。若后续引入成熟调度算法，应新增版本化调度策略并为历史日志保存策略标识，不能把规则迭代伪装为 FSRS。

### F4 的研究设计边界

建议让参与者完成内容和难度相近的任务，使用预先确定的任务顺序或平衡顺序；统一任务说明、测量时间点和问卷。实验人数、招募方式、题目审校、授权/同意、缺失数据处理均需记录。Paas 心理努力评分、用时和测验表现是不同观测指标，不能把单一分数等同于完整的认知负荷，更不能预先宣称系统已减负。正式统计方法应根据实际样本与导师要求确定。

## 与参考论文的对应

- 马杰等《基于相关性提示的知识图谱问答》支撑现有的“图谱检索—相关性排序/评分—提示词—答案”论文复现模块。新增的分层提示应复用真实候选证据及现有校验，不改变已有方法实验的控制条件。
- 刘娟等《数字化学习中认知负荷智能化评估研究进展》为 F4 的评价维度与方法边界提供依据。平台首期可用非侵入式自评、学习任务用时和测验数据；该综述并不意味着本项目实现了生理信号采集或智能化认知负荷识别算法。
- Qwen 基座与 LoRA 的 2×3 矩阵属于模型/方法研究模块，应单独标注、单独统计；不得混入 DeepSeek 方法对照组。LoRA 训练标签未教师审校前，其结果只作探索性证据。

## 通用验收与范围约束

- 所有学习计划、复习记录、测量数据和报告按登录用户隔离；管理员不能无依据读取不必要的敏感自评数据。
- 时间/间隔算法使用注入时钟进行单元测试，覆盖夏令时/时区、跨日、逾期和重复提交等边界。
- 新表只追加 V6+ Flyway 迁移，不改已执行迁移；失败时不得把未完成任务或无效复习写成成功。
- M1 首版经验估计：错题复习5分钟、课程阅读15分钟、单题练习10分钟；这些是计划排程假设，不代表实测时长。每日预算为5–240分钟。重新生成保留已完成与已跳过任务；未完成目标的任务不能绕过真实学习行为标记完成。
- Python Bridge、Mecha-QA 与 NebulaGraph 图空间保持现有只读边界；新功能复用已有检索契约。
- 不把合成训练标签、开发冒烟测试或问答文本相似度冒充教师评测、学习效果或认知负荷结论。
